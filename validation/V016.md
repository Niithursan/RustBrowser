## Reproduction and implementation

- A deterministic delayed failure event delivered while the failed toolbar was
  retained caused a second recovery and failure record. After adding a monotonic
  toolbar identity, stale events do not consume the restart budget. Natural
  occurrence/frequency of this scheduling race was not established.
- Exhausting the recovery budget and delivering further current-view failures
  admitted repeated terminal alerts. The same native assertion now admits one
  alert per window. Tests replace the modal itself with a counter at its admission
  point; no unattended test dismisses a production error dialog.
- An infinite loop in the disposable toolbar renderer stayed hung for 30 seconds;
  no native Unresponsive notification was observed during that interval. An
  injected classified Unresponsive event, with the renderer genuinely hung,
  now starts a five-second health grace and then uses the existing bounded rebuild.
  Measured replacement in development runs was approximately 5.1 seconds after
  that event. A responsive toolbar answers the fixed local script without a
  restart; duplicate reports do not extend its deadline. This does not detect
  every hang, and the test does not establish watchdog coverage.
- Native baseline: content browser accelerators enabled, zoom control disabled,
  Ctrl+F/P/plus absent from the application shortcut map. GUI Ctrl+F found three
  matches and Ctrl+P opened preview; Ctrl+plus did not change zoom. Content zoom
  is now enabled, and keyboard/menu commands target only a visible website tab.
- Printing from More initially left focus on the toolbar, so Escape did not
  cancel preview. A native focus assertion reproduced this. Moving focus to the
  content controller before ShowPrintUI makes the same assertion pass.

The toolbar keeps native browser accelerators, zoom and context menus disabled.
Custom shortcuts route to the selected content engine, with existing AltGr and
Ctrl+Shift+P pin behavior preserved. Local browser panels reject content tools.
No page receives privileged IPC, and printing uses browser preview without a
shell, silent print, automatic save or elevation.

Zoom belongs to the open content controller. New same-site controllers start at
100%, switching preserves each controller's factor, and closing/recreating a view
does not restore zoom from Rust Browser's session. Zoom is not added to either
storage format. WebView2 can also change its factor during navigation; the badge
reads the live controller rather than assuming a cached percentage.

## Native and GUI evidence

`native_toolbar_engine_failure_is_recovered` covers real fixture browser/renderer
termination, a real renderer hang with an injected report, responsive health
checks, stale events, the terminal-alert gate, content-view preservation and
normal shutdown. `native_content_find_zoom_print_boundary` covers native settings,
menu IPC, two same-site tabs, fresh controllers, live zoom display/reset, native
find matches, print initiation/focus, shutdown and session exclusion. Ctrl+wheel
is delivered as a window message only to a render-host descendant of the owned
content controller. It exercises the native zoom event without global input or
cursor movement; it is not a physical mouse-device test.

`native_private_content_tools_are_ephemeral` runs the same workload in a private
window, checks the actual private profile for session/library/diagnostic writes,
checks that the normal root was not used for those records, and requires private
engine profile cleanup after shutdown.

Eight compiled product mutations were rejected by semantic assertions: stale
source guard, alert gate, hang handling, content zoom disabled, native toolbar
tools enabled, missing zoom notification, incorrect find term and omitted print
focus. No compile failure counted as a caught mutant. Raw owned logs are outside
Git at `<workspace>/work/v16/mutations.json` and its referenced directory.
An additional compiled mutation disabling content zoom also failed the new private
workload's semantic assertion; see `work/v16/mutations-private-zoom-off.json`.
There are nine mutation runs across three native workloads, covering eight
distinct defect types.

Development GUI checks used a fresh disposable profile and controlled loopback
HTML. Confirmed blank native find UI, text entry, three highlighted matches,
Enter advancing to the second match, More find, keyboard zoom in/out/reset,
More zoom in/out, zoom with toolbar focus, badge reset and More print preview.
The print focus fix passed the native regression. A GUI recheck with the 0.16.0
debug build restored the disposable session, opened preview from More and Ctrl+P,
and cancelled both with Escape. Keyboard zoom and More reset were rechecked, and
the owned window exited normally. Full local gates are recorded in VALIDATION.md
when completed.
No actual printer output, PDF write, real account, camera or system setting was
used in these checks. Development GUI evidence is not owner acceptance.

The native runtime did not complete a search callback for an empty query, although
the GUI opened. A nonempty query completed and matched three fixture occurrences.
The automated test uses that actual query through the same content adapter; it
does not infer blank-dialog visibility from a callback.

Relevant official APIs:
[browser shortcuts](https://github.com/MicrosoftDocs/edge-developer/blob/main/microsoft-edge/webview2/concepts/browser-features.md),
[Find.Start](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2find),
[ShowPrintUI](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2_16),
and [controller zoom events](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2controller).
Programmatic ZoomFactor assignment does not emit the user zoom notification;
application commands render explicitly and user/native changes use the event.
Older runtimes missing Find/print interfaces show a retry/update error rather
than introducing a custom find bar or weakening the engine.
